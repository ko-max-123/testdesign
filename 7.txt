「報告」をテーマにした課題解決用の簡易Webアプリを作成してください。

## 目的

日々の業務報告が「事実の羅列」になってしまい、上司が状況判断しづらいという課題を解決したいです。

そのため、報告者がフォームのテンプレートに沿って入力することで、以下が伝わる報告書を作れるようにしてください。

* 何をしたか
* 現在どういう状態か
* 問題・リスクはあるか
* 次に何をするか
* 上司に判断・確認してほしいことは何か

## 実行環境の条件

* インストール不要
* サーバ不要
* npm不要
* 外部ライブラリ不要
* CDN不要
* `index.html` をブラウザで直接開くだけで動くこと
* HTML / CSS / JavaScript を1ファイルにまとめてください
* できるだけ環境依存を少なくしてください
* Microsoft Edge / Google Chrome で動作する想定にしてください

## 作成するもの

単一ファイルの `index.html` を作成してください。

画面構成は以下にしてください。

1. タイトルエリア
2. 報告基本情報エリア
3. 報告フォーム編集エリア
4. プレビューエリア
5. 保存・読み込みエリア
6. エクスポートエリア

## 1. タイトルエリア

画面上部に以下を表示してください。

* アプリ名：業務報告テンプレート作成ツール
* 説明文：事実の羅列ではなく、状況判断しやすい報告書を作成するためのツールです。

## 2. 報告基本情報エリア

以下の入力欄を用意してください。

* 報告タイトル
* 報告日
* 報告者名
* 対象業務・プロジェクト名

報告日は初期値として今日の日付を自動入力してください。

## 3. 報告フォーム編集エリア

報告内容を入力するフォームを表示してください。

初期状態では、以下のテンプレート項目を用意してください。

1. 本日の実施内容
2. 現在の状況
3. 発生している問題・リスク
4. 原因・背景
5. 次の対応
6. 上司に確認・判断してほしいこと
7. 補足

各項目は以下の構成にしてください。

* 項目名
* 入力欄
* 補足ガイド文

例：

項目名：現在の状況
補足ガイド文：完了・進行中・遅延・保留など、判断しやすい状態を書いてください。
入力欄：textarea

## フォーム項目の操作

各フォーム項目に対して、以下の操作ができるようにしてください。

* 項目を追加
* 項目を削除
* 項目名を変更
* 補足ガイド文を変更
* 上へ移動
* 下へ移動

重要：
エクスポート時は、画面上に表示されているフォーム項目の順番通りに出力してください。

## 4. プレビューエリア

入力内容をもとに、報告書のプレビューをリアルタイム表示してください。

プレビューは以下のような形にしてください。

# 報告タイトル

* 報告日：
* 報告者：
* 対象業務・プロジェクト：

## 本日の実施内容

入力内容

## 現在の状況

入力内容

## 発生している問題・リスク

入力内容

## 原因・背景

入力内容

## 次の対応

入力内容

## 上司に確認・判断してほしいこと

入力内容

## 補足

入力内容

入力が空の項目も、見出しは表示してください。

## 5. 保存・読み込みエリア

保存ボタンを設置してください。

保存ボタンを押すと、現在の入力内容とフォーム構成を保存してください。

保存データには以下を含めてください。

* 報告タイトル
* 報告日
* 報告者名
* 対象業務・プロジェクト名
* フォーム項目の順番
* 各フォーム項目名
* 各補足ガイド文
* 各入力内容
* 保存日時

保存した内容は一覧で表示してください。

保存一覧には以下を表示してください。

* 報告タイトル
* 報告日
* 保存日時

保存一覧から1件を選択すると、その保存内容をフォームに復元して、見返し・編集できるようにしてください。

保存一覧には以下の操作も用意してください。

* 読み込み
* 削除

## 保存方法について

サーバなし・インストールなしで動かすため、通常の保存はブラウザの `localStorage` を使用してください。

ただし、課題仕様として保存フォルダ名は `save` としたいです。

ブラウザ単体では、ユーザー操作なしにPC内の `save` フォルダへ自動保存できないため、以下の方針で実装してください。

* アプリ内保存：localStorageに保存する
* エクスポート時のファイル名には `save_` または `report_` を付ける
* 画面上に「ファイルとして保存する場合は、任意で `save` フォルダを作成して保存してください」と小さく説明を表示する
* プロジェクト構成の説明として、保存先フォルダ名は `save` とする

可能であれば、Edge / Chrome の File System Access API に対応している場合のみ、ユーザーが `save` フォルダを選択して保存できる補助機能を追加してください。ただし、この機能が使えない環境でもアプリの基本機能は動くようにしてください。

## 6. エクスポートエリア

以下の形式でエクスポートできるボタンを用意してください。

* Word
* txt
* Markdown
* JSON

### Word出力

外部ライブラリなしで実装してください。

厳密な `.docx` ではなく、Wordで開けるHTML形式または `.doc` 形式で問題ありません。

ファイル拡張子は `.doc` とし、Wordで開いたときに報告書として読める形式にしてください。

### txt出力

プレーンテキスト形式で出力してください。

### Markdown出力

見出しに `#` や `##` を使い、Markdown形式で出力してください。

### JSON出力

以下のような構造で出力してください。

{
"title": "",
"date": "",
"reporter": "",
"project": "",
"items": [
{
"label": "",
"guide": "",
"value": ""
}
],
"savedAt": ""
}

重要：
JSONの `items` は、画面上のフォーム項目の順番通りに出力してください。

## UIデザイン

3時間程度で作る課題なので、凝りすぎないシンプルなデザインにしてください。

ただし、以下は意識してください。

* 入力エリアとプレビューエリアが分かりやすい
* ボタンの役割が分かりやすい
* 保存一覧が見やすい
* 報告書として出力したときに読みやすい
* スマホ対応は最低限でよい
* PCブラウザで見やすいレイアウトを優先する

できれば、画面を左右2カラムにしてください。

左側：

* 基本情報
* フォーム入力
* 項目追加・削除・並び替え

右側：

* プレビュー
* 保存一覧
* エクスポートボタン

## 実装上の注意

* JavaScriptは分かりやすくコメントを入れてください
* 関数を適度に分けてください
* 変数名は分かりやすくしてください
* エラーが起きにくいようにしてください
* 空欄があってもエクスポートできるようにしてください
* 削除操作は確認ダイアログを出してください
* 保存データがない場合は「保存データはありません」と表示してください
* HTMLファイル単体で完結するようにしてください
